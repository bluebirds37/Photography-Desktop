# 开发指南

## 1. 环境要求

- Windows 10/11
- Rust stable（当前验证版本 1.97）
- 可选：系统 FFmpeg（程序也可自动安装组件）
- 推荐：Node.js 24（仅用于辅助脚本，不参与构建）

## 2. 构建与运行

```bash
cargo build --release
target/release/timelapse_assistant.exe
target/release/tlcore.exe --help
```

开发构建：

```bash
cargo build
cargo run --bin timelapse_assistant -- "D:/photos/seq"
cargo run --bin tlcore -- analyze "D:/photos/seq"
```

测试：

```bash
cargo test --lib
cargo check --all-targets
cargo fmt
```

## 3. 模块结构

```text
src/
  main.rs                 GPUI 应用入口，创建窗口
  lib.rs                  导出 core / ui
  core/
    model.rs              数据结构、项目持久化、调整列
    analysis.rs           导入、EXIF、RAW/预览解码、缩略图、视觉亮度
    loess.rs              LOESS 局部线性回归
    deflicker.rs          视觉去闪烁
    holy_grail.rs         曝光曲线与自动优化
    transition.rs         关键帧插值
    xmp.rs                XMP 边车
    ffmpeg.rs             FFmpeg 组件管理
    image_pipeline.rs     图像显影与亮度统计
    render.rs             并行渲染与 ffmpeg 编码
  ui/
    app.rs                GPUI 主界面、状态机、异步消息
    graph.rs              亮度/曝光曲线绘制
  bin/tlcore.rs           无界面 CLI
```

## 4. 数据模型

### 4.1 Sequence

```rust
pub struct Sequence {
    pub folder: PathBuf,
    pub name: String,
    pub images: Vec<ImageEntry>,
    pub settings: SequenceSettings,
    pub workflow: WorkflowState,
    pub render: RenderSettings,
    pub sort_by_time: bool,
    pub hdr: bool,
    pub saved_at: Option<String>,
}
```

### 4.2 ImageEntry

每帧保存：

- 文件名、时间戳
- 相机曝光、ISO、快门、光圈
- 亮度与白平衡统计
- 缩略图相对路径
- 文件大小/修改时间（用于增量导入）
- 调整值、关键帧、跳过标记、错误信息

### 4.3 调整列

`AdjustColumn` 统一描述：

```text
曝光、色温、色调、对比度、高光、阴影、白色、黑色、饱和度、自然饱和度
```

新增一列时：

1. 在 `Adjustments` 增加字段；
2. 在 `AdjustColumn::get/set/label/range` 增加分支；
3. 在 `transition::interpolate_adjustments` 的列数组中添加；
4. 在 UI `adjust_tab` 增加滑块；
5. 在 XMP 读写和渲染管线中接入（如需要）。

### 4.4 项目文件

路径：

```text
<sequence>/.lrtassist/project.json
```

写入采用临时文件 + rename，避免半写坏文件。自动保存由 UI 定时触发，关闭窗口时也会保存。

## 5. UI 与异步

### 5.1 实体

`TimelapseApp` 是 GPUI 实体，持有：

- 当前序列、选中帧
- 预览图片、缩略图缓存
- 页签、状态、提示
- FFmpeg 组件状态
- 后台消息通道

### 5.2 后台任务

耗时任务通过 `std::thread` 执行，结果通过 `crossbeam-channel` 发送：

```text
导入、预览生成、去闪烁、XMP、渲染、FFmpeg 安装
```

UI 在 `start_loop` 中每 70ms 轮询消息并调用 `cx.notify()`。渲染进度、安装进度、错误提示都走同一通道。

### 5.3 UI 约定

- 所有颜色来自顶部常量（`BG0` / `BG1` / `ACCENT` 等）
- 面板统一使用 `section_card`
- 按钮统一使用 `button` / `settings_button`
- 可枚举选项使用分段按钮，不使用文本框
- 长路径使用 `short_path` / `short_text`，避免横向溢出
- 单帧调整头部采用三行布局：标题、文件名、操作行

## 6. FFmpeg 组件管理

### 6.1 目录

```text
components/ffmpeg/
  versions.json
  <version>/
    ffmpeg.exe
    ffprobe.exe
    *.dll
  downloads/
```

`versions.json`：

```json
{
  "selected": "6.1.1",
  "versions": [
    { "version": "6.1.1", "dir": "6.1.1", "source": "system", "installed_at": "..." }
  ],
  "auto_attempted": true
}
```

### 6.2 解析顺序

1. 已选中的内置版本
2. `TIMELAPSE_FFMPEG` 环境变量
3. 系统 FFmpeg

### 6.3 安装流程

- 系统导入：复制 `ffmpeg.exe`、`ffprobe.exe`、`ffplay.exe` 和同目录 DLL
- ZIP/TGZ：解压到临时目录，递归查找 `ffmpeg.exe`，复制其目录内容
- 下载：流式写入临时文件，显示下载进度，再解压/注册
- 安装完成后写入 manifest 并选中新版本

### 6.4 安全性

- ZIP 使用 `enclosed_name` 防止路径穿越
- tar 使用标准解包路径校验
- 卸载只允许删除组件根目录下的直接子目录
- 编码预设使用枚举映射，避免拼接任意 ffmpeg 参数

## 7. 渲染管线

### 7.1 帧渲染

`render_sequence`：

1. 可选写 XMP
2. 创建临时帧目录
3. 线程池并行处理每帧
4. 解码 → 调整 → 缩放/裁剪 → 锐化 → PNG
5. 可选运动模糊
6. 调用 ffmpeg 编码
7. 清理临时帧（除非勾选保留）

### 7.2 编码参数

`video_args` 单独生成参数，便于单元测试：

- H.264 / H.265：preset、CRF 或 VBR
- ProRes：profile 3，忽略码率
- 帧率来自 `RenderSettings.fps`

新增编码选项时，优先扩展 `video_args` 并补充测试，不要在 `Command` 拼接处直接写逻辑。

## 8. 测试与验证

当前测试覆盖：

- LOESS：常数、线性、尖峰、窗口
- 去闪烁：高频闪烁、恒定模式、已有曝光
- HG：曝光阶跃、偏移、优化范围
- 关键帧：首尾保持、平滑模式
- XMP：新建、更新、文件名
- 图像管线：sRGB 往返、曝光、缩放
- 项目：自然排序、持久化
- 渲染参数：CRF、码率、ProRes
- FFmpeg：版本字符串清理、本地探测

端到端验证建议：

```bash
tlcore demo ./.demo
tlcore analyze ./.demo
tlcore hg ./.demo
tlcore keyframes ./.demo
tlcore transition ./.demo
tlcore deflicker ./.demo
tlcore report ./.demo

ffprobe -v error -show_entries format=duration:stream=codec_name,width,height -of default=noprint_wrappers=1 ./out.mp4
```

## 9. 发布

### 9.1 构建

```bash
cargo build --release --bins
```

产物：

```text
target/release/timelapse_assistant.exe
target/release/tlcore.exe
```

### 9.2 打包

推荐目录：

```text
dist/
  timelapse_assistant.exe
  tlcore.exe
  components/            可选，首次运行也会自动生成
```

如果目标 exe 正在运行，Windows 会锁定文件；此时可以：

1. 关闭运行中的实例后重新构建；或
2. 使用临时 `[[bin]]` 名称构建并复制；或
3. 直接把新构建复制到新的发布目录。

### 9.3 依赖镜像

本机 `.cargo/config.toml` 使用 rsproxy 镜像。若在网络受限环境构建失败，可改用其他可用镜像或代理。

## 10. 常见开发问题

### 编译慢

GPUI 与图像/RAW 依赖首次编译较慢；后续增量构建正常。发布构建启用 thin LTO，链接阶段也会较慢。

### exe 无法覆盖

说明有实例正在运行。关闭实例，或构建到新的目标目录/发布目录。

### 图片在列表中空白

- 检查 `.lrtassist/thumbs` 是否存在
- 检查解码错误（行末 `!`）
- RAW 可回退到内嵌 JPEG；若仍失败，检查文件完整性

### UI 更新不刷新

后台消息处理后必须调用 `cx.notify()`；新增异步任务时沿用 `Msg` + 轮询模式。

### 渲染参数无效

确认 `RenderSettings` 新字段已加入 `video_args`，并补充参数测试。ProRes 不读取 CRF/码率。
